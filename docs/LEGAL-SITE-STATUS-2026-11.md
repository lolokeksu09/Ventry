# Ventry — правовые сведения на сайте: статус внедрения

**Дата:** 18 ноября 2026 г.  
**Назначение:** отслеживать не общие юридические обещания, а подтверждённые шаги для информационного сайта Ventry.

## Выполнено

- Опубликована страница `/legal/` с фактическим статусом Ventry: **личный онлайн-проект физического лица без регистрации ИП/ООО**.
- В качестве контакта владельцем согласован `ventrybusinesswork@gmail.com`; добавлены `mailto:` и ссылки из футеров главной, «Расчёта» и самой юридической страницы.

- В `sitemap.xml` включён `/legal/`; `tools/verify-site.py` контролирует полноту карты сайта, контактную ссылку и канонические адреса.
- На сайте по исходникам не обнаружены регистрация, формы для отправки данных, платёжные операции или сторонние аналитические SDK.
- В `deploy/Caddyfile` отсутствует явная директива access `log`; **это не доказывает**, что журналы Docker/инфраструктуры/VDS не обрабатывают технические данные.

## Подтверждение конфигурации Docker от владельца (18.11.2026)

Сведения получены из выполненного на VDS `docker inspect` для `ventry-web-1`:

```text
{"Type":"json-file","Config":{}}
LogPath=/var/lib/docker/containers/<id>/<id>-json.log
```

- **Установлено:** Docker записывает stdout/stderr контейнера в локальный файл `json-file`; явных параметров `max-size`/`max-file` в конфигурации контейнера нет.
- **Не установлено:** действительно ли в журнал попадают IP-адреса, URL-запросы, User-Agent или другие идентификаторы; сколько сообщений и байт уже сохранено; есть ли внешняя ротация/журналирование хостинга.
- **Технический риск:** при стандартных настройках `json-file` автоматическая ротация отключена; журнал способен расти без ограничения. Перед изменением драйвера/параметров логирования проверить текущие требования к диагностике, retention и способ пересоздания только `ventry-web-1`.
- **Следующая проверка:** получить только размер и число строк журнала (без текстов, IP-адресов и другой потенциально чувствительной информации), затем проверить наличие реальных записей HTTP access и политику хранения.
- **Не считать аудит № 152-ФЗ завершённым.** Этот результат подтверждает место служебных журналов контейнера, а не классификацию/перечень персональных данных.

Документация: https://docs.docker.com/engine/logging/drivers/json-file/ ; https://caddyserver.com/docs/caddyfile/directives/log .

### Результат проверки размера `json-file` (со слов владельца)

- Размер на момент проверки: **4 949 байт**.
- Количество строк: **21** (для `json-file` обычно соответствует 21 записи).
- Время изменения файла: **2026-11-18 04:47:01.351890562 +0000** (UTC).
- **Подтверждено:** журнал небольшой на момент проверки.
- **Не подтверждено:** наличие или отсутствие в строках персональных данных, IP-адресов и запросов; характер сообщений (запуск/ошибки/access); период хранения и ротация. Время изменения рядом с деплоем не является доказательством состава записей.
- **Следующий шаг:** изучить только обезличенные счётчики структурных полей JSON-журнала; не публиковать сырые журналы. После этого определить, какие технические данные и где сохраняются.

### Структурная проверка `json-file` (результаты владельца, 18.11.2026)

Анализ выполнен неразрушающим Python-скриптом, который читает внутренние JSON-сообщения Caddy и считает типовые признаки.

| Проверка | Количество |
|---|---:|
| Всего записей | 21 |
| `http.log.access*` или вложенный `request` | 0 |
| Типовые ключи `remote_ip`, `client_ip`, `remote_addr` | 0 |
| Типовые ключи `User-Agent`, `user_agent` | 0 |
| Уровни `warn`/`error` | 4 |
| Сообщения, не разобранные как JSON-объект | 0 |

**Ограничение доказательств:** 0 по конкретным ключам и структурам не равен 0 персональных данных; не просмотрены тексты сообщений, другие ключи и журналы ОС/провайдера. Четыре предупреждения/ошибки требуют безопасной классификации без публикации сырых сообщений.

**Технический следующий шаг:** настроить ограничение роста Docker `json-file` через `logging.options.max-size` и `max-file` в `compose.yaml`, но только после оценки воздействия пересоздания контейнера и согласования параметров; текущая конфигурация `Config: {}` ограничений не содержит. Это ограничивает объём, но не является сроком хранения данных.

## Юридически НЕ закрыто

1. **Полная идентификация владельца.** Только бренд и почта не заменяют сведений о владельце и адресе. Для исполнения ч. 2 ст. 10 № 149-ФЗ нужно определить применимые требования к публичным сведениям физического лица и предоставить корректные идентифицирующие/адресные данные. Не публиковать домашний адрес или паспорт по умолчанию без оценки и решения владельца.
2. **Персональные данные.** Не установлены реальные технические журналы и их сроки хранения, видимость IP-адресов, доступ поставщиков и место обработки. При наличии обработки персональных данных оценить обязанности оператора по № 152-ФЗ, в том числе публикацию политики (ст. 18.1) и уведомление Роскомнадзора (ст. 22), если нет предусмотренного законом исключения.
3. **Правообладатели.** Правовой статус изображений, баннеров, фирменного знака и иконок следует подтверждать источниками и правами использования. `site/fonts/OFL.txt` находится в репозитории, но это не распространяется на другие ресурсы.
4. **Отдельный продукт.** Правовой аудит будущего приложения «Расчёт» не завершён; публичная веб-страница приложения не является сервисом учёта долгов.

## Проверка серверных настроек без публикации личных данных

После входа на VDS выполнить только неразрушающие команды:

```bash
cd /opt/ventry
docker compose --project-name ventry ps
docker inspect --format '{{json .HostConfig.LogConfig}}' ventry-web-1
docker inspect --format 'LogPath={{.LogPath}}' ventry-web-1
grep -nE '(^|[[:space:]])log([[:space:]]|\{|$)|root \*|header' deploy/Caddyfile
```

Результаты отражают лишь конфигурацию. **Не выкладывать сырые журналы, IP-адреса, секреты или доступ к SSH в Issues/PR.** Дополнительно проверить конфигурацию логирования ОС и хостинг-провайдера, поскольку `docker inspect` не покрывает их полностью.
