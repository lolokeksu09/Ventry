# Ventry Delivery — активация и Ed25519 (staging)

Реализация сервера и администраторского клиента, не production. Тарифы прежние. Код активации не является ссылкой APK. Пробный код резервирует возможность однократного пробного периода: начисление 7 дней происходит атомарно при первой привязке. Платный код требует действующего оплаченного срока, при активации и переносе не изменяет срок. Ручная оплата остаётся отдельной операцией.

## Протокол
Админ: POST /api/v1/subscriptions/{id}/activations с event_id UUID и trial boolean возвращает activation metadata и code (64 lowercase hex, 256 random bits); GET того же пути — последние 100 записей без хэшей; POST /activations/{event}/revoke отзывает непогашенный код. Административный listener остаётся loopback. Код действует 24 часа; одна активная выдача на подписку. Если изменились ревизия/оплата/привязка между выдачей и погашением — отозвать старый код и выдать новый. Код и refresh secret различны.

Клиент: генерирует и сохраняет до первого запроса случайный installation UUID и 32 random bytes refresh secret (hex). POST /api/v1/activate, Authorization Bearer CODE, JSON {installation_id, product, refresh_secret}. Повтор с тем же кодом, установкой и refresh secret в срок действия кода безопасен; другой получатель не может повторно использовать код. POST /api/v1/entitlement, Bearer REFRESH_SECRET, JSON {installation_id,product}. Отдельная сессия на подписку, старый refresh secret или прошлая ревизия привязки не допускаются даже после переноса обратно. UUID не аппаратное удостоверение; необходим защищённый Android Keystore storage и дополнительная оценка угроз для production.

Ответ — JSON {key_id,payload_hex,signature_hex}. Ed25519 подпись **точных байтов** UTF-8 JSON, не повторно сериализованного объекта. key_id = SHA-256 raw 32-byte public key, signature 64 bytes. Payload v=1, issuer=ventry-delivery, product, package_name, subscription_id, installation_id, revision, issued_at, valid_until, lease_until (UTC epoch seconds), may_create_debt. Клиент проверяет подпись закреплённым публичным ключом, версию/продукт/package/установку, типы и диапазоны claims, freshness, монотонность revision/time, срок; неизвестный key_id отклоняет. До 72 часов офлайн, не дольше оплаченного срока. После истечения подписки signed may_create_debt=false; чтение, погашение, экспорт и восстановление книги не зависят от лицензии. 24/72 часа — предложенные технические параметры. Мгновенно отозвать офлайн-разрешение невозможно. При сбое подписи после коммита повтор безопасен; клиент обязан сохранить refresh secret до отправки. Не хранить bearer в логах, URL, backup или незашифрованной persistent storage. Ограничения публичного staging: отдельный global rate 60/min; перед production нужны TLS, per-source limits и выделенная auth инфраструктура. Не считать текущий RC лицензированным.

## Ключ и проверки
DELIVERY_SIGNING_KEY_FILE — файл отдельного 32-byte seed Ed25519 в hex, owner-only 0600; никогда не использовать Android signing key, SSH key, admin token. CI генерирует новый тестовый ключ и не публикует его. В production ключ и публичный pin, ротация и восстановление требуют отдельного согласованного rollout; не генерировать новый ключ при каждом production старте. Migration 004 добавочная. Тесты сервера: две одновременные активации с одинаковым credential, повтор чужого кода, независимая OpenSSL проверка подписи и подмены, trial, renewal, transfer, ручная перепривязка, revoked/expired, кросс-продукт, отсутствие сырого токена в истории. Ventry Admin: отдельный экран лицензии, выдача и Share, история, отзыв; проверка API на эмуляторе. Android «Расчёт» verification/enforcement, production signing key, безопасный удалённый вход администратора и развёртывание остаются открытыми. Существующий APK RC не меняется.
