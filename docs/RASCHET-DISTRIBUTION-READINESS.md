## Подготовка подписанного кандидата
Перед выбором нового артефакта для выдачи проверьте, что успешный Actions workflow `Raschet public licensed candidate` был запущен вручную на main, SHA совпадает с принятой ревизией, артефакт не истёк. Возьмите SHA256 ZIP из GitHub Actions API (не из архива); публичный ключ Delivery — из действующего проверенного deployment, не из ZIP. Выполните локально с Android SDK build-tools:

```bash
python3 delivery/bin/verify-candidate.py Raschet-licensed-candidate.zip \
  --archive-sha256 "$ARCHIVE_SHA256" --revision "$REVISION" \
  --public-key "$DELIVERY_PUBLIC_KEY" --version-code 36 \
  --version-name 0.31.0-beta.1 \
  --apksigner "$ANDROID_HOME/build-tools/35.0.0/apksigner" \
  --aapt "$ANDROID_HOME/build-tools/35.0.0/aapt"
```

Команда читает архив с лимитом размера, отвергает лишние/дублированные имена и несоответствие доверенному хэшу, сверяет метаданные и фактическую подпись, пакет, версию, минимум SDK, компоненты лицензирования и четыре JNI ABI. Сертификат закреплён действующим release.json. Не устанавливает APK, не меняет сервер, не создаёт запись release.json и не открывает выдачу. Проверка манифеста/receipt не доказывает исполнение лицензионного guard или наличие правильного Ed25519 pin в байткоде: доверяем только точной успешно проверенной сборке CI, дополнительно обязательны активация/обновление/истечение/перенос и восстановление на физическом телефоне. Результат `verified_candidate_not_approved` — проверка идентичности, а не утверждение коммерческой готовности. Старый release.json по-прежнему указывает 0.30 RC и НЕ является лицензированным коммерческим артефактом. Для реальной выдачи нужна отдельная проверенная смена версии и ограниченное включение download. Новый статус облачных копий не изменяет условия продажи, хранения или возвратов.

## Подготовленный пакет и привязка выдачи к версии

Необязательный `--stage-root /existing/private/staging` у verify-candidate.py после проверки создаёт новый уникальный каталог с APK, candidate.json и маркером VERIFIED_NOT_APPROVED. Не заменяет текущий APK, не меняет release.json, не открывает выдачу; повторная подготовка не перезаписывает прежний пакет. Маркер не является разрешением на коммерческую поставку.

Новый Admin отображает версию, versionCode, ревизию, размер, SHA-256 APK и сертификата. Оператор подтверждает конкретную сборку; запрос issue содержит expected_release_sha256. API проверяет хэш до записи в БД, возвращает 409 release_changed при устаревшем выборе, а клиент обновляет сведения. Старые клиенты без поля остаются совместимыми в staging. Уже выданная ссылка привязана к прежнему SHA; после смены версии не должна показываться как действительная ссылка на новую. Старый сервер не принимает новое поле: требуется обновить API до нового Admin, без небезопасного fallback. Изменение production APK и включение коммерческой выдачи остаются отдельным этапом после физической приёмки. Не изменены лицензии, подписки или схема БД.
