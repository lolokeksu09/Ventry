# Ventry Admin — native staging 0.1.0-alpha.1

Связано с Issue #75. Единая админка проектов, не отдельное приложение на каждый продукт. Kotlin, Jetpack Compose, AndroidViewModel/StateFlow, тот же Rust/Axum API и PostgreSQL. Независимый модуль admin-android, package dev.ventry.admin.staging для debug, minSdk 26, targetSdk 35. Production APK не выпускается этой веткой.

## Реализовано
- Каталог реальных проектов с метриками, регистрация продукта, тарифы, проектный список подписок с пагинацией и локальным поиском среди загруженных строк, прямой поиск по UUID.
- Карточка клиента (только UUID на текущей серверной схеме), статус, срок, тариф, история подтверждений, привязка/перенос, создание подписки и ручное подтверждение начисления. Суммы в копейках, серверный источник цен.
- Сохранение неподтверждённой оплаты в приватных preferences перед сетевым запросом: origin, subscription UUID, event UUID, план, сумма. После сбоя повтор с прежними параметрами; локальный журнал очищается только после ответа или явного подтверждения оператора после проверки истории. Токены и ключи в журнал не записываются. Удаление приложения или данных Android удалит журнал: перед повтором сверять историю.
- Проверенный release metadata, отдельная выдача одноразовой ссылки APK, отзыв и Android Share. Код активации и подписанный entitlement не реализованы; скачивание не означает подписку.
- Сетевой клиент без перенаправлений и хранения credential; HTTPS с системной проверкой TLS, HTTP только для debug loopback 127.0.0.1; экран защищён FLAG_SECURE. Токен оператора вводится вручную и хранится в памяти ViewModel; не сохраняется в saved state, preferences, APK или логе. Выход прекращает локальную сессию, отменяет запросы, но не отменяет уже подтверждённую на сервере транзакцию.

## Приёмка и запуск
CI Ventry Admin Android собирает debug APK и инструментальные тесты, выполняет unit/lint, проверяет подпись и package, поднимает изолированный настоящий Delivery/PostgreSQL с проверенным Raschet APK, устанавливает APK и тестовый APK на Android API35. adb reverse соединяет телефон эмулятора с закрытым сервером. Compose тест проверяет вход, каталог, тарифы и выход; native transport test — создание отдельного проекта/тарифа/подписки, привязку, повтор начисления без изменения срока, изоляцию и отказ неправильному ключу. Это staging, не проверка реального удалённого входа с телефона владельца. Секреты тестового сервера генерируются только в runner.

Сборка: gradle -p admin-android testDebugUnitTest lintDebug assembleDebug --no-daemon. APK — app/build/outputs/apk/debug/app-debug.apk. В staging не вводить production-ключи. Ни на VDS, ни на публичном сайте изменения не развёртываются.

## Открытые границы
Перед реальной продажей — защищённый удалённый контур для телефона (приватная сеть или выделенный HTTPS с короткими отзываемыми сессиями, device binding/Keystore и отдельным аудитом), подписанная production-сборка админки и entitlement в «Расчёте», миграция и безопасное обновление, резервное копирование, юридическая и платёжная готовность. Имена/контакты клиентов, изменение действующих тарифов, общие финансы, многооператорные роли и периодическая блокировка сессии остаются отдельными этапами. UI сейчас показывает UUID, не вымышленные имена. Не открывать loopback API публично; существующий долгоживущий staging Bearer не является утверждённой production-аутентификацией.

## 0.5.0-alpha.1 — рабочие действия подписки

На карточке вместо выпадающего списка показываются все пять действий: лицензия, выдача APK, оплата, устройство, история и данные. Для новой подписки и ожидающей активации сразу открывается раздел лицензии. UUID и обновление доступны в истории; явная передача номера подписки не раскрывает токены или коды. UI интеграция использует новую синтетическую подписку реальной тестовой БД, проверяет доступность действий, диалог выдачи пробного доступа (отмена без выдачи) и переход в историю. Схема БД/API/секреты/production не меняются.
