# План изменения Ventry (шаблон)

**Этот файл — образец, не активный план.** Для небольшой задачи достаточно PR. Для многоэтапной задачи веди один реестр; если есть Issue/трекер — укажи ссылку вместо копии.

## Основание
- Цель и источник разрешённого объёма: не заполнено.
- Базовые `main` SHA, рабочая ветка, diff: не зафиксированы.
- Входит / не входит: не заполнено.
- Сохраняемые контракты и опасные области: не заполнено.
- Для нового проекта: один минимальный сквозной сценарий первой версии и его проверяемый критерий: не определён.

## Проверка и выпуск
- Необходимые L1–L5 и обязательные gates: см. [TESTING-LEVELS.md](../../TESTING-LEVELS.md), конкретная область ещё не оценена.
- Новый каркас: установка зависимостей, сборка, запуск, сквозной сценарий — не выполнены / не применимы с обоснованием.
- Ошибка: воспроизведение исходного сбоя **или** причина недоступности + регрессия изменённой версии.
- UI: реальная проверка обновлённого экрана, действий и размеров.
- Данные: резервирование, совместимость и восстановление, если применимо.
- Кто и что разрешил для записи, merge и поставки: не определено.

## История и передача
Законченные этапы записывай с SHA, ссылкой на точную проверку и остатком. Не создавай второй реестр REQ-ID. После передачи обнови [CONTINUATION.md](CONTINUATION.md), если задача длительная. Статусы требований и поставки независимы.
