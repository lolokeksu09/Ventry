# Ventry 2.0 — P0: сохранность локальной книги

## Подтверждено по исходникам
- `app.js` сохранял полную книгу через `localStorage.setItem`; обработчик события storage обновлял UI, но не сериализовал чтение и запись.
- Обычное восстановление уже сравнивало исходный JSON после сохранения копии, однако эта проверка не была атомарной с записью.
- Основной и технический HTTPS-адреса — разные origins, следовательно, их localStorage и IndexedDB изолированы.

## Реализация
- Web Locks: эксклюзивная блокировка по ключу книги и сравнение точного исходного снимка под блокировкой. Устаревшая операция не заменяет более свежую книгу. Ключ и JSON-формат сохранены.
- Все изменения клиентов, операций, отмены, импорта, восстановления и перезапуска примера проходят единый save. Отдельные ключи демо и личной книги сохраняются.
- При конфликте пользователь получает указание открыть форму заново; при отсутствии Web Locks запись блокируется, экспорт остаётся доступным.
- Старый домен не перенаправляется автоматически, так как это скрыло бы доступ к его отдельному хранилищу. Интерфейс объясняет перенос и даёт прямые ссылки.

## Безопасный перенос
1. На старом адресе в исходном браузере открыть личную книгу, скачать защищённую копию.
2. На основном адресе скачать отдельную копию имеющихся там записей, если они есть.
3. Восстановить старую копию на основном адресе, только если пользователь согласен заменить книгу целиком. Автоматическое объединение двух книг пока не реализовано.
4. Сверить клиентов, операции и остатки. Старые данные не удалять до проверки.

## Границы и критерии
- Web Locks координирует только обновлённые вкладки одного origin. Перед работой после деплоя необходимо закрыть старые вкладки и открыть сайт заново; старый код не участвует в блокировке.
- Кросс-доменная синхронизация и автоматическое объединение не реализованы. Ручной перенос сохраняет доступ к исходным данным. Если обе книги содержат нужные операции, требуется отдельный сценарий безопасного объединения.
- В существующую suite `node --test tests/raschet-backups.mjs` добавлены проверки конфликта, одновременной первой записи, изоляции демо, отсутствия блокировки, отказа записи и устаревшего восстановления.
- Не считать браузерную приёмку пройденной без сценария в двух вкладках Chromium, включая одновременное сохранение, удаление данных и восстановление.
- Production не изменён, данные и форматы не мигрируются автоматически.
