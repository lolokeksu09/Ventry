# Ventry Delivery — этап 1: подписки «Расчёта»

Решение владельца 27.11.2026: подписка, а не разовая покупка. Сайт Ventry остаётся каталогом; отдельное ядро выдачи не развёртывается автоматически и не работает с долговыми книгами клиентов.

## Продуктовый контракт

- 7 дней пробного доступа; 299 ₽ за месяц, 799 ₽ за три месяца, 2 490 ₽ за год. Все тарифы включают функции, обновления, поддержку и перенос на другое устройство. Суммы в копейках, один источник истины: таблица `delivery.plan`.
- Периоды оплаченного доступа — календарные месяцы в UTC; пробный период — ровно 7 дней. Продление заранее добавляется к действующему сроку, после истечения — начинается от времени подтверждения. Первоначальная платная подписка отсчитывается от подтверждения, пробная — после привязки установки. Это предложенные технические детали, не публичная оферта.
- После окончания подписки нельзя создавать новые долги; просмотр, погашение и экспорт существующих данных должны работать. Сохранить резервное копирование, восстановление и исправление исторических ошибок; не стирать книгу и не отключать доступ к ней из-за сервера. Конкретный guard для коррекций и отмен проверяется перед изменением APK. Пока APK не содержит лицензионного ограничения.
- Один клиент и продукт — одна подписка, одно активное непрозрачное installation ID. Перенос не уменьшает оплаченный срок. Пробный период однократен для клиента/продукта и известного ID установки. Случайный ID установки не является аппаратным идентификатором; повторная регистрация после переустановки не гарантированно распознаётся, поэтому пробный доступ выдаёт оператор.
- Оплата подтверждается вручную, без автосписаний. Идентификатор подтверждения (UUID) повторно используется при retry; изменение параметров под старым UUID отклоняется. Учитывать реальный платёж только один раз: оператор должен сохранить его UUID; это не автоматическая сверка банка или фискальный чек.

## Реализованное ядро (не production)

`delivery/migrations/001_subscriptions.sql` — транзакционная схема PostgreSQL 17: тарифы, подписки, история привязок и начислений. Привязка/перенос и продление сериализуются блокировкой строки подписки; повтор того же события возвращает первоначальный результат. Цена и срок записываются в журнал операции. Нет внешних сетевых запросов, секретов, имён, телефонов, банковских реквизитов или данных о долгах. Доступ PUBLIC отозван. Функции SECURITY INVOKER; локальный оператор с авторизованным доступом к отдельной БД доверенный. Прямой доступ БД не предоставлять клиентам; будущий сервис получает отдельную минимальную роль, а не роль владельца.

`delivery/bin/admin.sh` — локальный операторский CLI (не веб-панель), стандартная аутентификация PostgreSQL. Не публиковать PostgreSQL в интернете. На существующей production БД миграцию не применять. CI создаёт отдельную одноразовую БД. Для разработки на отдельно подготовленном PostgreSQL:
```bash
psql -X -v ON_ERROR_STOP=1 -f delivery/migrations/001_subscriptions.sql
bash delivery/bin/admin.sh plans
bash delivery/bin/admin.sh
```
Последняя команда выводит справку и возвращает 2, если команда не указана. Для create, bind, trial, renew, transfer, status и history см. справку; UUID создаются оператором и сохраняются в его защищённом журнале. Обязательные переменные подключения зависят от окружения (libpq). Не передавать пароль в командной строке; использовать системную конфигурацию/секреты. Реальные действия пока не разрешены на VDS.

## Последовательность поставки

| Этап | Результат и критерий |
|---|---|
| 1 — основа | Изолированная БД, CLI, цены, история, тесты повторного начисления, переноса, истечения и отказа неавторизованной роли. CI PostgreSQL, включая одновременные renew. |
| 2 — Rust/Axum API | Отдельный внутренний контейнер/роль, защищённая админка, аутентификация, авторизация каждой операции, журнал администратора, идемпотентность, лимиты запросов. Релизный каталог из проверенных подписанных артефактов. |
| 3 — выдача APK | Короткоживущая высокоэнтропийная ссылка, хранение только хэша токена, ограничение срока и повторов, проверка SHA-256 и закреплённого сертификата, исключение токена из логов. Обычная публичная ссылка на GitHub RC не является лицензией. |
| 4 — Android | Kotlin/MVVM, проверка подписанного entitlement Ed25519 с публичным ключом, подписанные claims продукта, установки, срока, ревизии и разрешений, секрет подписи только на сервере. Тесты повреждения, истечения, часов, переноса, сбоев сети и миграции. Не вводить обязательную интернет-проверку для чтения/оплаты/экспорта книги. Предложить политику периодического обновления, чтобы у старого офлайн-устройства после переноса оставался лишь ограниченный срок доступа; мгновенный офлайн-отзыв невозможен. |
| 5 — запуск | Изолированная БД и резервное копирование, закрытый staging, signed APK upgrade с RC2/RC1 без потери данных, выданная лицензия → загрузка → установка → активация → оплата → продление → истечение → перенос → восстановление; проверка законной модели приёма платежей и условий продажи до первой реальной продажи. |

## Границы этапа

Не изменены сайт, Caddy, действующий Docker Compose, VDS, секреты и Android. Серверный Rust/Axum, Ed25519 и web-панель ещё не реализованы. Цена согласована для разработки, но не публикуется как оферта, реальный приём денег не запускается. Не считать выпуск коммерчески готовым только потому, что prerelease APK опубликован. Сохранить действующий статический allowlist и изоляцию локальных данных. Политика срока офлайн-entitlement, восстановления/переноса и условия возвратов должны быть проверены до эксплуатации.

## Проверки

`.github/workflows/delivery-core.yml` запускает shell syntax, миграцию, тесты SQL, конкурирующее продление и CLI на чистом PostgreSQL 17 в контейнере без сетевых портов и production-секретов. На момент подготовки PR PostgreSQL/Docker недоступны в текущей рабочей среде: runtime gate ожидает CI. Не выдавать написанный тест за пройденный.
