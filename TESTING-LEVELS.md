# Уровни проверок Ventry: L1–L5

Основано на приложенном **Project Workflow Standard v1.0**. Уровни выбирают по риску и обязательным gates проекта, а не по количеству изменённых строк и не по режиму Light/Full. Это рабочее соглашение проекта, а не внешний отраслевой стандарт.

| Уровень | Назначение | Пример доказательства для Ventry |
| --- | --- | --- |
| **L1 — базовая корректность** | Синтаксис, конфигурация, текст, маршруты, простые инварианты | `node --check site/app.js`; `python3 tools/verify-site.py`; `docker compose -f compose.yaml config --quiet`; проверка относительных ссылок документации |
| **L2 — затронутая область** | Позитивный и значимый отрицательный путь изменённого поведения | `node tests/copy-link.cjs` для отказа и повтора копирования; браузерная проверка изменённого UI |
| **L3 — связанные сценарии** | Сквозное взаимодействие компонентов и границы доверия | `tests/security-http.sh` для живого Caddy в тестовом контейнере, реальная навигация и CSP |
| **L4 — приёмка кандидата** | Все обязательные gates кандидата закрыты успехом либо разрешёнными **активными** EXC-ID, с сохранением реальных статусов | `validate` из [deploy.yml](.github/workflows/deploy.yml) на точной ревизии и отдельная запись о проверенных UI-сценариях |
| **L5 — проверка поставки** | Установлена и работает **именно доставленная** версия | `deploy` из [deploy.yml](.github/workflows/deploy.yml) на `main`, SHA из `/version.json`, валидный HTTPS, `/healthz`, 308/404 и реальные страницы |

Область L4 не гарантирует визуального качества автоматически; для редизайна обязательна отдельная браузерная приёмка. Ни один уровень не подтверждается только названием CI-job.

## Как выбирать проверки

1. Установи обязательные gates Ventry, включая секреты, безопасность и работающий деплой. Они не отменяются режимом Light.
2. Документация: L1 на ссылки и согласованность; команды выполняй, если они изменены и среда доступна.
3. Правка поведения или UI: L1 + L2 на новую версию; для затронутых связей — L3. При ошибке сохрани воспроизведённый исходный сбой **либо** ограничение воспроизведения; отдельно проверь регрессию после исправления.
4. Авторизация, приватность, платежи и данные: положительный и отрицательный L2/L3; при миграции — восстановление. Сейчас на публичном сайте Ventry нет денежных операций.
5. Новый каркас: сразу проверить установку зависимостей, сборку и запуск, затем минимальный сквозной сценарий (если применимо); файлы без запуска — не рабочая версия.
6. При разрешённом merge/выпуске: L4 по политике проекта. После разрешённой production-поставки: L5 по фактическому артефакту.

## Пять независимых статусов

| Объект | Статусы |
| --- | --- |
| Требование | не оценено / в работе / выполнено / частично / заблокировано / исключено владельцем |
| Проверка | не выполнено / успех / сбой / недоступно / не применимо |
| Этап | не начат / в работе / завершён / заблокирован / отменён |
| Исключение | активно / истекло / закрыто |
| Поставка | подготовлено / опубликовано и проверено / поставка неуспешна / требуется восстановление |

Нельзя превращать `skipped`, `pending`, `cancelled`, отсутствие тестов или блокировку браузера в успех. Результат относится только к конкретному коду, конфигурации, данным и окружению; повторно используй успешное доказательство лишь при неизменных входах. Для кода без Git фиксируй SHA-256 артефакта.

## Обязательные исключения EXC-ID

Обойти обязательный gate можно лишь при явном разрешении уполномоченного лица в пределах действующей политики. Запиши `EXC-001` (уникальный ID), gate, сценарий и точную ревизию, причину и остаточный риск, источник разрешения, срок или событие истечения, компенсирующие меры и критерий закрытия.

- Gate с активным применимым исключением обозначай «закрыт по EXC-ID», но исходную проверку оставляй `не выполнено`/`сбой`/`недоступно` по факту — **не успех**.
- Истёкшее исключение, другое окружение, SHA или выпуск его **автоматически не переносят**. Политика безопасности может запрещать обход.
- Исключение не даёт разрешения на выпуск. Деплой зависит от конкретного разрешения владельца, см. [AGENTS.md](AGENTS.md).

## Доказательства

Для каждой существенной проверки фиксируй **точную ревизию**, сценарий/команду, окружение, результат, ссылку на конкретный запуск/снимок/лог и ограничения. Сканер и unit-тест не подтверждают наличие визуально правильного экрана; локальный HTTPS-тест не равен проверке опубликованного сайта. Не публикуй секреты, персональные данные и приватные логи.

Текущие команды и работа CI определяются конфигурацией Ventry, см. [README.md](README.md), [deploy.yml](.github/workflows/deploy.yml), [security-audit.yml](.github/workflows/security-audit.yml) и [security-http.sh](tests/security-http.sh).
